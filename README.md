# UnixFit Local

## Обновление FTMS

Данные дорожки: 2ACD. Управление: 2AD9. Приложение подписывается на indications, запрашивает управление и проверяет ответы FTMS. Для каждого соединения используется последовательная очередь GATT. Скорость ограничена 12 км/ч и прочитанным диапазоном устройства. Стоп использует FTMS Stop (08 01), а не неизвестные proprietary-команды.

Для проверки закройте FitShow, подключите дорожку и сначала проверьте показатели. После подключения ожидается сообщение «FTMS: управление разрешено». При отказе скопируйте журнал на вкладке Debug. Проверять движение следует только с физическим ключом безопасности и свободным полотном. Программный стоп не является гарантированным экстренным выключателем. Если предыдущая команда ещё не получила ответ, новая команда, включая Stop, отклоняется; при опасности используйте физический ключ.

Автокоррекция, программы, история и proprietary-управление пока не завершены. Приложение не поддерживает фоновую тренировку: держите его открытым. Этот архив содержит исходники, не APK. Полная Android-сборка проверяется через GitHub Actions. Локальный gradlew требует установленного Gradle 8.7 и JDK 17.

## Старое описание (для справки)

Локальное Android-приложение для управления беговой дорожкой UNixFit-990x через BLE. Приложение не использует интернет и не содержит разрешения `android.permission.INTERNET`.

## Возможности

- Сканирование устройств `FS-*`, `FitShow` и BLE Heart Rate.
- FTMS service `0x1826`, данные `0x2ACD`, Control Point `0x2AD9`.
- Одновременное подключение дорожки и пульсометра `0x180D/0x2A37`.
- Ручное изменение скорости с ограничением по умолчанию 12 км/ч и аварийный стоп.
- Debug-журнал сервисов, характеристик, TX/RX и поле для proprietary UUID/hex-команд через BLE-слой.
- Room Database для локального хранения программ.
- Kotlin, Jetpack Compose, MVVM/StateFlow, API 21-34.

## Сборка без Android Studio

```bash
chmod +x gradlew
./gradlew assembleDebug
```

Готовый APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

GitHub Actions запускается на push в `main` и вручную через вкладку Actions. Артефакт называется `UnixFit-Local-debug`: откройте завершённый workflow, блок Artifacts и скачайте APK. На телефоне разрешите установку APK из используемого файлового менеджера и установите файл.

## Использование

1. Установите APK и выдайте разрешения Bluetooth. На Android до 12 также требуется геолокация для BLE-сканирования.
2. Нажмите `Сканировать`. Для дорожки выберите устройство с именем `FS-`/`FitShow`; для нагрудного датчика выберите устройство Heart Rate.
3. На вкладке `Тренировка` используйте `+`, `−` и `ЭКСТРЕННЫЙ СТОП`.
4. На вкладке `Debug` проверьте обнаруженные сервисы и характеристики. Если FTMS Control Point не принимает команды, используйте найденный proprietary write UUID и hex-формат команды в настройках/диагностическом слое.

Пример формата программы для импорта/экспорта:

```json
{
  "name": "Интервальная тренировка",
  "description": "5 интервалов высокой интенсивности",
  "segments": [
    {"duration_sec": 300, "speed_kmh": 5.0, "name": "Разминка"},
    {"duration_sec": 120, "speed_kmh": 10.0, "name": "Интервал 1"},
    {"duration_sec": 120, "speed_kmh": 6.0, "name": "Отдых"},
    {"duration_sec": 120, "speed_kmh": 11.0, "name": "Интервал 2"},
    {"duration_sec": 300, "speed_kmh": 4.0, "name": "Заминка"}
  ]
}
```

## Важное ограничение FitShow

FTMS стандартизует сервисы и формат данных, но отдельные FitShow-модули могут использовать proprietary команды. Универсальный байтовый протокол нельзя достоверно определить статически. Поэтому приложение логирует GATT-сервисы и TX/RX, позволяет выбрать UUID записи и отправить тестовые hex-байты. Для конкретного FS-BT-C1 может понадобиться один сеанс сравнения команд с официальным FitShow.
